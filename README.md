# Product Card AI

Локальный прототип AI-помощника для подготовки черновиков товарных карточек контрольно-измерительных приборов для B2B-интернет-магазина.

Сервис принимает исходные данные о приборе в JSON, формирует SEO-текст с помощью LLM через Groq API и возвращает структурированный результат. Перед публикацией карточку должен проверить контент-менеджер.

## Возможности

- Ввод данных через веб-страницу или REST API.
- Генерация SEO-заголовка (до 70 символов), SEO-описания (800–1200 символов), 3–5 поисковых запросов и краткого коммерческого блока.
- Возврат структурированных технических характеристик **без изменения исходных значений**.
- Обозначение недостающих входных полей и предупреждений.
- Копирование карточки из веб-интерфейса в JSON, Markdown или обычном тексте.
- Валидация запросов и ответов через Pydantic v2, обработка ошибок API и невалидного ответа модели.

## Стек

- Python 3.12+, FastAPI, Uvicorn
- Pydantic v2, pydantic-settings
- Groq API через OpenAI-совместимый SDK (`openai`)
- HTML, CSS, Vanilla JavaScript — без отдельного frontend-сборщика
- uv — зависимости и воспроизводимое окружение
- pytest, pytest-asyncio, httpx — тестирование
- Ruff, Mypy (strict) — стиль и типизация
- Docker Compose — дополнительный способ локального запуска

## Быстрый старт (uv)

Требуются Python 3.12+ и [uv](https://docs.astral.sh/uv/).

```powershell
# Из корня репозитория
uv sync
Copy-Item .env.example .env
```

В `.env` укажите полученный в [Groq Console](https://console.groq.com/keys) API-ключ:

```dotenv
GROQ_API_KEY=gsk_...
GROQ_MODEL=openai/gpt-oss-120b
LLM_TIMEOUT_SECONDS=30
```

Точное имя модели и её доступность зависят от лимитов и настроек аккаунта Groq. Если настройки модели, бюджета токенов или reasoning вынесены в `Settings`, при необходимости укажите соответствующие переменные из `.env.example`.

Запуск:

```powershell
uv run uvicorn app.main:app --reload
```

Откройте:

- Веб-интерфейс: http://127.0.0.1:8000/
- Swagger UI: http://127.0.0.1:8000/docs
- Health check: http://127.0.0.1:8000/health

**Без API-ключа** можно запускать автоматические тесты, поскольку LLM подменяется тестовым клиентом. Для реальной генерации ключ необходим.

## Запуск через Docker (опционально)

Требуется установленный Docker Desktop / Docker Engine с Docker Compose. Создайте `.env` аналогично инструкции выше, затем запустите:

```powershell
docker compose up --build -d
docker compose logs -f app
```

Интерфейс будет доступен по адресу http://127.0.0.1:8000/. Остановка:

```powershell
docker compose down
```

> Docker — необязательный способ запуска. Сборка зависит от доступа к реестрам образов и Python-пакетов. Если порт 8000 занят локальным Uvicorn, остановите его перед запуском контейнера.

## Использование API

`POST /api/v1/cards/generate` — принимает исходные данные товара и возвращает карточку.

Пример запроса:

```json
{
  "name": "Манометр показывающий DM 02",
  "manufacturer": "Манотомь",
  "specs": {
    "диапазон измерений": "0–1,6 МПа",
    "класс точности": "1,5",
    "присоединение": "G1/2",
    "диаметр корпуса": "100 мм"
  },
  "description": "Прибор предназначен для измерения избыточного давления."
}
```

Основные поля успешного ответа:

| Поле | Содержание |
|---|---|
| `seo_title` | SEO-заголовок, не более 70 символов |
| `seo_description` | SEO-описание, 800–1200 символов |
| `specifications` | Словарь исходных характеристик |
| `search_queries` | 3–5 поисковых запросов |
| `commercial_block` | Краткий блок для менеджера |
| `missing_fields` | Отсутствующие исходные поля с пояснениями |
| `warnings` | Предупреждения для проверки |

Ошибки обрабатываются на сервере: невалидный ввод — HTTP 422, ошибки LLM — HTTP 502, отсутствие API-ключа — HTTP 503, таймаут — HTTP 504. Браузер показывает понятное сообщение, а не технический код. 

## Архитектура

Проект — небольшой **слоистый монолит**. База данных и отдельный frontend-сервер не используются.

```text
src/app/
├── main.py                 # Инициализация FastAPI, HTML-страница
├── api/
│   ├── routes.py           # HTTP endpoints и ошибки
│   └── dependencies.py     # Dependency Injection
├── schemas/
│   ├── product.py          # ProductInput
│   ├── card.py             # GeneratedCardContent, ProductCard
│   └── missing_field.py    # MissingField
├── services/
│   └── card_generator.py   # Оркестрация и бизнес-правила
├── integrations/
│   └── llm_client.py       # Protocol и реализация клиента Groq
├── prompts/
│   └── product_card.py     # Промпты
├── config.py               # Настройки через переменные окружения
└── static/
    └── index.html          # Минимальный интерфейс

tests/                       # Unit- и API-тесты
examples/                    # Примеры входных данных и результатов
```

Поток запроса: **Frontend / API → `ProductInput` → `CardGenerationService` → `LLMClient` → Pydantic-валидация → `ProductCard`**.

`CardGenerationService` зависит от типизированного интерфейса `LLMClient` (`Protocol`), а не от конкретного провайдера. Это позволяет подменять внешний API в тестах. Зависимости FastAPI задаются через `Annotated` и `Depends`.

## Промпты и контроль достоверности

Промпты вынесены из LLM-клиента в `src/app/prompts/product_card.py`. Они требуют использовать только входные данные, не добавлять неподтверждённые технические свойства, соблюдать русский язык, структуру и ограничения карточки. Содержимое технического описания рассматривается как данные, а не как инструкции для приложения.

В ходе разработки были опробованы модели GPT-OSS 20B и 120B. На тестовых запросах модель 120B дала более сдержанный технический текст; для прототипа выбрана `openai/gpt-oss-120b` с низкой температурой (`0.1`) и `reasoning_effort="low"`. Это результат ограниченной ручной проверки, а не систематического бенчмарка.

Для устойчивой структуры используется Structured Outputs (JSON Schema), а затем — независимая валидация Pydantic. Если ответ модели не соответствует контракту, сервис делает ограниченную повторную попытку.

**Защита фактов:** `specifications` копируются из `ProductInput`, а не генерируются LLM. При отсутствии одновременно `specs` и `description` генерация не выполняется. Недостающие базовые поля отражаются в `missing_fields`.

**Ограничение:** Structured Outputs и Pydantic проверяют формат и ограничения, **но не гарантируют истинность свободного SEO-текста**. Модель всё ещё может делать неподтверждённые выводы о совместимости, монтаже или условиях эксплуатации. Перед публикацией необходима проверка человеком.

## Тестирование и качество кода

```powershell
uv run pytest -q
uv run ruff check .
uv run ruff format --check .
uv run mypy src tests --strict
uv build
```

Тесты покрывают валидацию входа, ограничения выходной схемы, неполные данные, успешную генерацию, некорректные ответы LLM, повторную попытку, ошибки провайдера и маршруты FastAPI. Основные тесты не используют платный API: вместо него применяется Fake LLM Client.

Для отдельной ручной интеграционной проверки запустите приложение, откройте Swagger UI и отправьте пример из `examples/product_1.json`.

## Ограничения и возможные улучшения

- Это локальный прототип, а не готовая CMS: нет авторизации, базы данных и истории генераций.
- Гарантируется сохранение переданных структурированных характеристик, но не полная фактологическая корректность свободного текста.
- Требование 800–1200 символов может конфликтовать с недостаточным объёмом исходных фактов; корректнее вернуть ошибку, чем придумывать свойства прибора.
- Валидация не проверяет технический паспорт по внешним источникам.
- Внешний API зависит от доступности моделей, сети и лимитов Groq.
- Для развития: отдельная проверка фактов, набор эталонных товаров для оценки генераций, управление версиями промптов, экспорт файлов, мониторинг ошибок и времени ответа.

## Безопасность

API-ключ считывается только сервером из `.env`/переменных окружения. Файл `.env` исключён из Git и Docker build context. 

## Статус

MVP для локальной демонстрации. Текстовые блоки — **черновики**, требующие проверки контент-менеджером перед публикацией.

### Происхождение демонстрационных результатов

Результаты в `examples/results/` отредактированы вручную и не являются неизменёнными ответами API. Второй товар — синтетический учебный пример.

Заполненные значения характеристик сохраняются; пустые значения возвращаются как «Данных нет» и перечисляются в `missing_fields`. Если все значения пусты и описание отсутствует, LLM не вызывается.
